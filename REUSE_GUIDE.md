# Reusing the Helpdesk UI and submission protections

This update adapts the November 2026 PMMA Helpdesk improvements to this starter's Laravel 12 structure. It keeps the starter's configurable branding, authorization, references, audit trail, and Open / In Progress / Resolved / Closed status workflow. No Helpdesk production records, employee registration policy, PMMA letterhead, environment files, credentials, or application database were copied.

## Upgrade an existing copy

1. Review and merge these source changes into your application. Resolve business-model and route differences deliberately.
2. Install the locked Composer dependencies with `composer install`.
3. Run `php artisan migrate` (use `--force` for an authorized production deployment), then `php artisan optimize:clear`.
4. Deploy the `public/assets` additions with the Blade/controller changes. Keep the normal HTTPS, APP_DEBUG=false, authentication and CSRF setup.
5. Run `php artisan test`. The starter uses an isolated in-memory SQLite database for tests.

The two new migrations add a durable submission-receipt table and service display ordering. Deploy them before serving the new controllers. Never copy `.env`, `vendor`, sessions, cached configuration or uploaded files from another app. Existing ticket data is retained.

## Use the submission guard in another module

Keep `SubmissionGuard`, the `submission_receipts` migration, named rate limiters and exception response when replacing the sample ticket module. The guard is independent of Ticket and accepts a trusted Eloquent model class and a callback:

```php
$request->validate([
    'submission_token' => ['required', 'uuid'],
    'title' => ['required', 'string', 'max:200'],
]);

[$record, $created] = app(\App\Support\SubmissionGuard::class)->run(
    $request,
    'project-requests',       // A distinct, constant scope for this operation.
    ProjectRequest::class,    // Server-controlled class; never take this from input.
    fn () => ProjectRequest::create(['title' => $request->string('title')->toString()]),
);
```

Give each new form a UUID generated by `Str::uuid()` on the server. Preserve it with `old('submission_token', $token)` after validation errors. The staff modal creates a fresh UUID with `crypto.randomUUID()` each time it opens and keeps it through retries. HTTPS is required in deployment. Do not regenerate the token on each click or retry. Require this token on every create endpoint; use `throttle:submissions` after session/auth middleware.

The unique database claim is inserted before the write callback. The claim, resource and model-generated timeline entries commit or roll back together on the default database connection. Concurrent attempts with the same operation key cannot both create a resource. A replay retrieves the existing resource. The owner is the authenticated account or the anonymous browser session, and the operation scope separates modules. This protects resubmitting the same form; a brand-new token intentionally permits a new request. It does not deduplicate semantically identical concerns from different browsers.

The callback must return a persisted Eloquent model with a numeric primary key on the default database connection. Keep email, external API calls and other irreversible side effects outside this transaction; queue them after commit and only when `$created` is true. The guard cannot atomically commit writes to another database or an external service. If you delete a referenced resource, a replay returns 404 rather than recreating it. Keep receipt records as long as you need durable replay protection; pruning them ends that protection for old tokens.

## Configure rate limiting

`config/submissions.php` defaults to 5 attempts per 10 minutes per account/session, plus a 100-attempt shared-IP ceiling. Validation failures and replays also count as attempts. Offices behind a shared NAT have separate session limits. A new browser session can reset the session bucket; the IP bucket is the additional ceiling, not a complete bot defense. Choose limits appropriate to the workflow and configure trusted proxies for your actual deployment so client IP detection is correct.

Use the database or Redis cache shared by all app servers. Do not use the array cache in production. Tests intentionally use the array store. JSON clients should read HTTP 429 / Retry-After; the editor displays the returned message. The existing login failed-attempt limiter remains separate. Rate limiting and idempotency complement authorization, CSRF and validation.

## Scripts and plugins

The UI uses the existing locally bundled Bootstrap Icons, jQuery, DataTables and Chart.js. The wizard, grouped navigation, back-to-top and submission feedback use browser APIs and plain JavaScript; no new paid plugin or frontend package is required. Rate limiting is Laravel's built-in middleware, not a JavaScript plugin. Keep THIRD_PARTY_NOTICES.md and vendor license headers.

Laravel 9's RouteServiceProvider/exception-handler files were adapted to Laravel 12's AppServiceProvider and bootstrap/app.php. Do not copy those framework entrypoints between different Laravel major versions without adapting them.
